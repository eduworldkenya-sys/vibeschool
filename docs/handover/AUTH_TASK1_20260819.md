## P0/P1 root causes and branch repairs

1. Access authority and onboarding could disagree for admins. `get_my_auth_journey_state()` now owns the canonical profile/role/domain/onboarding/destination state; legacy resolver RPCs are projections of it.
2. Teacher onboarding and its callback fallback referenced nonexistent `teacher_classes.is_active`. The canonical resolver uses real schema contracts and membership-constrained class assignment.
3. The callback contained a second application-side authority fallback. It is removed: a PostgREST/schema failure now fails recoverably rather than selecting a weaker state path.
4. Negative-case injection exposed `min(uuid)` in learner identity resolution. `current_student_id()` and canonical learner resolution now count, reject ambiguity, and select the sole UUID deterministically.
5. Protected callback `next` paths with query/hash suffixes could bypass prefix classification because role checks used the full string. Role classification now normalizes to pathname before matching.
6. `/auth/error` recovery now has functional Try Again, Change account/logout, VibeSchool Home, pending state, local failure state, safe public copy, and >=48px primary tap targets.
7. Callback classification now preserves canonical resolver reasons for missing profile, missing admin authority, ambiguous learner identity, and unavailable accounts; only explicit `ROLE_UNCLAIMED` can enter self-service role claiming.
8. Client profile updates are grant-layer constrained so authority-bearing fields such as role, school authority, lifecycle/anonymization state and provenance cannot be directly rewritten by ordinary authenticated users.
9. The missing self-service `claim_my_initial_role(text)` contract is reconciled in repository migrations with one-time, identity-bound, non-admin semantics.
10. Repository truth now carries the safe `connect_teacher_to_directory_school()` implementation needed for deterministic reconstruction.
11. Repository migrations explicitly remove anonymous table privileges from the private core identity tables covered by Task 1.
12. TBL-011 exposed profile-shape drift: a literal profile column grant referenced `notification_prefs`, which is absent in a clean reconstruction at that migration point. The branch migration now intersects a fixed presentation-field allowlist with columns that actually exist, while permanently excluding authority-bearing fields.

## Canonical state machine

The database determines: authenticated identity → profile → account status → effective role authority → canonical domain identity/readiness → onboarding state → destination. Admin profile text alone is insufficient; admin/owner membership is required. Students require exactly one active canonical learner for ready state. Teachers require canonical teacher membership and a class assignment in the same school. Parents require a link to an active canonical learner. Ambiguous identity fails closed.

## Security properties

- Canonical identity resolver is `SECURITY DEFINER`, binds `auth.uid()` internally, fixes `search_path`, revokes PUBLIC/anon, and grants only authenticated/service_role.
- Legacy role/access/onboarding RPCs project the same resolver rather than competing with it.
- Anonymous execution of private identity RPCs is denied by repository contract.
- Callback deep links are role-checked after stripping query/hash for classification.
- No callback table fallback can bypass canonical authority.
- Profile edit authority uses a positive presentation-field allowlist intersected with reconstructed columns; authority-bearing fields never enter that allowlist.
