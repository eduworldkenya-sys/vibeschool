## P0 root causes confirmed

1. `get_my_auth_access_state()` correctly failed closed for an admin without admin/owner membership, but `get_my_onboarding_state()` independently returned `ready -> /admin` for any `profiles.role='admin'`. Two state machines could therefore disagree.
2. Production `get_my_onboarding_state()` referenced `teacher_classes.is_active`, but production `teacher_classes` has no `is_active` column.
3. The callback's PGRST202 emergency fallback repeated the same nonexistent `teacher_classes.is_active` dependency, so the recovery path could fail on the same teacher journey it was intended to rescue.

## Design correction

Migration `20260819013800_auth_canonical_journey_state.sql` establishes `get_my_auth_journey_state()` as the single database-owned journey authority for authentication state, profile state, canonical learner identity, role authority, onboarding state and destination.

Legacy consumers remain compatible, but `get_my_onboarding_state()`, `get_my_auth_access_state()` and `get_my_role()` become projections of the canonical journey resolver instead of competing implementations.

Teacher readiness is now proved only by canonical teacher school membership plus a teacher-class assignment in a school where the teacher has membership. No nonexistent `is_active` column is referenced. Parent readiness requires a link to an active canonical student. Admin readiness requires admin/owner membership. Student readiness requires exactly one active canonical `students.id`; zero routes to controlled claim recovery and multiple identities fail closed.

## Security properties

- Canonical resolver is `SECURITY DEFINER` only because it must inspect authority relations consistently; it binds `auth.uid()` internally, has a fixed `search_path`, and grants EXECUTE only to `authenticated` and `service_role`.
- Anonymous execution is revoked.
- Admin profile text alone does not confer admin authority.
- Missing or ambiguous learner identity never becomes a guessed learner.
- Teacher class readiness is constrained to a school where the teacher has canonical teacher membership.
- Parent readiness requires an existing active learner row.

## Regression protection

`scripts/test-auth-task1-state-machine.mjs` permanently asserts the five role lanes, canonical wrappers, minimum grants/search path, admin/teacher/parent/student authority predicates, absence of `teacher_classes.is_active`, and fail-closed middleware destination validation. The Auth & Onboarding workflow runs this contract before TypeScript, lint and the canonical production build.
