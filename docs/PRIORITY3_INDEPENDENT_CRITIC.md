## Machine CV and success function
The Critic is a Senior Educational Subject Editor / Independent Content Critic and, for certification, a Senior Chemistry Educational Editor. Its objective is correct defect discrimination, not approval rate, score inflation, agreement with the author, or number of criticisms.

## Independent input packet
A runtime integration must consume immutable artifact identity/version/content; canonical curriculum identity/outcomes/evidence; author worker/profile/subject/artifact-contract trace; provenance and planning evidence; P1 preflight/self-review/uncertainty; and the final merged P2 rubric/evaluation/blocker/evidence identities. Author self-score is evidence only and must be revealed after the Critic establishes its own judgment where practical.

## Review planning
The V1 profile makes the plan inspectable and uses bounded curriculum/pedagogy, scientific/subject, assessment, practical/safety and coherence/usability passes followed by findings synthesis and critic self-check.

## Findings and decisions
Findings carry critic execution, artifact/version, quality/profile identities, category, severity, affected section/outcome, evidence, reasoning, remediation, blocking status, confidence and uncertainty. Decisions are PASS, PASS_WITH_NOTES, REPAIR_REQUIRED, HUMAN_EDITOR_REQUIRED, EVIDENCE_REQUIRED and SAFETY_BLOCK. Critical unresolved uncertainty fails closed.

## Authority
The Critic is non-authoring, non-repairing, non-publishing and non-approving. It cannot clear an existing independent blocker. Repair requires a new artifact version and fresh Critic execution.

## Examination
The repository adversarial suite tests polished scientific falsehood, keyword-only curriculum coverage, shallow fluent teaching, meaningless activity volume, wrong assessment answers, answer/question mismatch, subtle safety omission, fabricated evidence, contradictory evidence, over-harsh style criticism and stale findings after repair. Calibration records both false negatives and false positives; rejecting everything is a failure.

## Priority 2 integration blocker
Priority 2 PR #402 currently contains the proposed sealed 11-dimension rubric, deterministic evaluator, frozen baseline and append-only evaluation ledger, but it is not merged. Priority 3 must not copy or redefine that taxonomy/rubric. Final P3 certification requires #402 (or its canonical replacement) to merge, then P3 must reconcile exact rubric/severity/evaluation identities and run the Critic against the sealed examination infrastructure without exposing gold answers to ordinary runtime context.

## Priority 4 handoff
Repair receives artifact version, precise finding, affected section/outcome, supporting evidence, required remediation and constraints. Repair cannot resolve its own finding; only a new artifact version plus fresh independent review can verify resolution.

## Production safety
This baseline adds no database migration, RPC, browser privilege, Worker Engine authority, runtime/autonomy change, publication path or production Supabase mutation. Operational DB/runtime integration must later preserve service-only execution, RLS/grants, explicit SECURITY DEFINER search_path, evidence immutability and existing Workforce governance.
