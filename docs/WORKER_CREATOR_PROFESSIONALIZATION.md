# Worker Creator Professionalization & Legacy Fleet Assurance

## Mission

Professionalize the existing Worker Factory rather than replace it. The existing demand evidence -> diagnosis -> blueprint -> creation contract -> SHADOW path remains canonical. This layer makes professional-worker quality, skills, risk, guardrails and independent assurance explicit and makes the existing fleet subject to the same standard.

## Evidence at start

Production has 12 `hq_workforce_workers`: 11 active legacy workers and one draft Content Factory canary. Existing WE-L7 already correctly prevents the factory from certifying/activating what it creates and enters created workers in SHADOW. The gap is that its creation contract is materially thinner than the professional standard learned from Content Factory P1-P4: it can create identity + one capability + one certified tool adapter without proving a complete competency/skills/context/memory/guardrail/adversarial assurance package.

## Professional standard

A professional worker now has an explicit versioned standard covering identity, mission boundaries, archetype, competency, certified skills, context, memory, tools, risk, guardrails, failure semantics, independent assurance, adversarial evidence, provenance, shadow/canary evidence, telemetry and recertification.

Competence and authority are separate. Creation never grants production authority. The Creator cannot self-certify its worker.

## Legacy fleet

All existing workers are registered as requiring recertification under the new standard. This is intentionally not an automatic downgrade or shutdown: runtime/authority changes belong to the governed Worker Engine lifecycle. The assurance registry makes the debt explicit and inspectable so higher-risk finance/security/publishing/operations workers can be examined first.

## Risk

- R0: observation/recommendation only
- R1: bounded reversible internal action
- R2: consequential scoped action with independent verification
- R3: high-consequence action requiring explicit human authority

Finance and Security default to R3; Publishing and Operations default to R2 until independently justified otherwise.

## Assurance

Each worker assurance record separates declared competency from demonstrated/certified skills. It requires independent assurance and adversarial evidence and preserves fresh verification after repair. Certification expiry/drift triggers belong to the existing recertification/runtime governance and must fail closed when wired into consequential authority.

## Deliberate boundary

This baseline does not claim that all 12 workers are now certified. It establishes the professional standard, assurance registry, deterministic legacy assessment entrypoint, risk classification and regression gate. Actual worker-by-worker certification requires independent evidence, not database seeding.

No factory activation. No heartbeat activation. No worker activation. No authority widening. No publication change.
