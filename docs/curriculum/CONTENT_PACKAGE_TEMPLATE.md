# VibeSchool Content Package Template — Grades 1–9

**START HERE FOR ALL CONTENT GENERATION:** [Single Canonical Content Generation Playbook](./CONTENT_GENERATION.md) defines the mandatory work sequence and single outcome package. Use this template as an optional **detailed evidence ledger for that same package**, never as another owner questionnaire, competing quality gate, content library or new production flow.

Use this template **per subject, term, sub-strand or batch**; declare the exact scope. It operationalizes [CONTENT_PRODUCTION_STANDARD.md](./CONTENT_PRODUCTION_STANDARD.md) under the current **[ChatGPT-Led Content Production Operating Model](./CONTENT_OPERATING_MODEL.md)**, without creating a separate approval system or content engine.

**This is a working manifest, not a form the VibeSchool owner must complete.** Production agents/teams populate it from source evidence, existing canonical records and performed checks. Do not replace missing evidence with signatures, guesses or “verified” labels.

**Operating interface:** Follow [CONTENT_GENERATION.md §0A](./CONTENT_GENERATION.md#0a-six-stage-daily-execution-short-operating-interface): Verify → Map/reuse → Produce → Validate → Integrate → Verify delivery/hand off. This template is the **existing canonical record of content-production progress**, not a second authoring system or a parallel approval ledger. Fill or update it from checked evidence; persist it via the approved repository/content workflow when work is actually performed. A chat draft that has not been persisted must be marked as such.

## 1A. Required KICD ↔ VibeSchool reconciliation gate — BEFORE any new content

**Stop-and-repair rule:** A content-generation chat must **first** read the applicable official KICD source and the current VibeSchool canonical curriculum for the exact grade/subject/scope; compare every required outcome and its strand/sub-strand, source revision, inquiry, experience, competencies, values, relevant PCIs, assessment scope and suggested lesson allocation. Do not use a prior claim of alignment or a matching heading as evidence.

| Required evidence | Recorded result |
| --- | --- |
| KICD official URL, revision, pages/sections and inspection date | |

| Requirement-by-requirement KICD locator → VibeSchool stable ID / semantic match | |
| Missing, partial, extra, conflicting or unverifiable requirements | |

| Recheck of corrected curriculum and existing Scheme/outcome bindings | |
| Final gate: `PASS` (all scope outcomes reconciled) or `BLOCKED_CURRICULUM_RECONCILIATION` | |

**Layered reconciliation evidence:** Record (A) the *whole-subject inventory* and edition differences, (B) the *per-outcome official-to-current-canonical crosswalk* and any safe repair/read-back, and (C) the set of individual outcomes **eligible for authoring**. An inventory does not count as verified outcomes. A truly reconciled sub-strand may proceed as an explicitly narrowed scope; all unresolved outcomes remain blocked. Record affected KICD source revisions/pages, historical ID/alias/teacher Scheme preservation and invalidated dependent checks. Do not treat April/July design editions as interchangeable without verifying their contents.

**If anything is missing or inaccurate, repair VibeSchool's canonical curriculum first, preserve existing IDs and school-owned history, and recheck.** Do not write notes, examples, exercises or teacher guidance for an unresolved scope. The user is not responsible for routine reconciliation. If the authoritative source or canonical map is unavailable, record `NOT_CHECKED` and the exact blocker; never guess, auto-certify or pass the gate. VibeSchool may word outcomes originally, but must preserve KICD's educational requirements without wholesale copying. This gate is separate from eventual content certification and publication.

### Learner content and teacher Lesson Notes are different but linked

Follow the [paired example and rules in the canonical playbook](./CONTENT_GENERATION.md#45-learner-content-vs-lesson-notes--two-views-of-one-verified-outcome). An outcome should have a complete, usable learner experience and enough teacher support to explain, question, check and intervene. Where a dedicated teacher-notes resource is educationally useful, record its actual contents and version. Both views must agree on the checked outcome, facts, worked steps, answers and resource lineage but need not be identical copies. Do not confuse teacher Lesson Notes with the Lesson Plan, and do not require a timetable for authoring or unscheduled preparation.

**Mathematics example acceptance:** A naked equation, final answer, unexplained formula, skipped meaningful transformation or unverified answer key is **incomplete**. Preserve the separate educational purposes in §3A; do not defer all activities or revision until an entire textbook is finished. For each row preserve:

- **Source gate:** KICD and current VibeSchool curriculum source version, `MATCH`/verified correction evidence, correct strand/sub-strand/outcome ID and relevant Scheme references.
- **Integrated authoring:** learner goal, prerequisites, explanation and reasoned worked/demonstrated model; age/ability appropriate guided and independent tasks, support and extension; later retrieval/application question and accurate feedback; teacher prompts, materials, timing and interventions. - **Checked answers:** mathematics working and units or appropriate sample responses/observation criteria; likely misconceptions, skipped/wrong/retry behaviour and learner-friendly feedback; genuine answer checking rather than generated guess.
- **Identity and exposure:** canonical chapter/resource IDs and item IDs/versions, source/content/exam-eligibility; known-answer examples and formative practice remain separate from secure formal-exam variants; no duplicate bank.

## 4. Practice and question integrity

For each reusable assessment item or set, preserve:

- stable **item ID**, associated curriculum outcome(s) and content taught;
- item type, prompt, language, accessible alternatives, complexity and intended feedback mode;
- correct answer **with explanation**, sample response or performance rubric and marking points; for mathematical items that test a method, supply a step-by-step worked solution with reasoning, formula definitions/substitution when applicable, correct units and a valid check;
- plausible but non-deceptive distractors where multiple-choice;
- misconception/feedback path for wrong, skipped or incomplete answers;
- eligibility for **exercise, topic practice, quiz and/or formal exam** without confusing their different rules;
- evidence the answer was actually checked.

**No separate question-bank copy for each consuming tool.**

### Distinct teaching and assessment uses

| Material/source item ID and version | Outcome ID | Learning role | Visibility/exposure | Eligible use (lesson exercise / Topic Practice / quiz / formal exam) | Answer authority and review state | Existing canonical ID / integration check |
| --- | --- | --- | --- | --- | --- | --- |
| | | Worked example / guided solution / independent question / unseen assessment variant | Revealed / practice / protected | | | |

- Keep a separate learning content identity for worked examples and revealed solutions: they **must not become protected-exam items by default**.
- Independent questions can be reused in eligible formative contexts only after answer/feedback validation; formal exams need appropriately protected, fresh or equivalent items with the existing exam policy and approval.
- Track variant relationships without confusing separate question identities. Do not duplicate the question bank or claim automatic live linkage from a planned row.
- Verify a representative wrong answer, skipped answer, retry, misconception feedback and securely withheld formal-exam answer.
- Distinguish **content-ready**, **connected to the question bank**, **approved for a stated assessment use**, and **deployed/learner-visible** with direct evidence.

### Editorial rubric — evidence-based and non-certifying

Rate only dimensions actually inspected on a **0–4 evidence scale** (0 absent/incorrect, 1 major defects, 2 partial, 3 sound, 4 strong) with the current outcome/package version and specific check. Weight curriculum fidelity **25%**, subject accuracy **20%**, conceptual understanding **20%**, practice and feedback **15%**, teacher usability **10%**, accessibility and inclusion **10%**. Compute an optional editorial percentage only when all six are checked (`sum(weight × rating / 4)`); never give untested dimensions an invented score. Follow the canonical [rubric and hard-failure precedence](./CONTENT_GENERATION.md#evidence-based-editorial-quality-rubric-diagnosis-not-certification). A critical alignment, correctness, safety, rights, security, indispensable resource or identity/link defect blocks its gate **regardless of score**. Model self-review does not replace required independent quality assurance.

| Dimension | 0–4 or NOT_CHECKED | Evidence/ref and version | Material defect / repair |
| --- | --- | --- | --- |
| Curriculum fidelity (25) | | | |
| Subject accuracy (20) | | | |
| Conceptual understanding (20) | | | |
| Practice and feedback (15) | | | |
| Teacher usability (10) | | | |
| Accessibility and inclusion (10) | | | |

**Three independent readiness decisions:** Editorial readiness (correct teaching package), delivery readiness (true authorized accessible routes), and learning effectiveness (actual student demonstration/retention). Record each separately; content counts and editorial scores are not learning outcome evidence.

**Result values:** PASS / FAIL / NOT_APPLICABLE (with reason) / NOT_CHECKED. Do not convert NOT_CHECKED into PASS. Attach references, version, time and actual verifier identity/type for substantive checks.

**Repair log:** What was wrong, which outcome/consumer it affected, where it was repaired in canonical content, and what was rechecked?

## 7. Release and learner-access evidence

- **Publishing authority:** Which *existing* authorization and release process applies?
- **Publishing result:** Exact release state and recorded evidence; do not infer from a merged PR.
- **Teacher journey:** Can a teacher view the curriculum and prepare scheme/lesson/notes/guide without a timetable? Does an actual scheduled lesson preserve its occurrence identity?
- **Learner journey:** Can an eligible independent learner open content, complete practice and receive correct feedback?
- **Assessment journey:** Do eligible questions load and mark correctly under their intended exam/practice policies?
- **Runtime evidence:** Environment, actual route, observed state, date, and any access restrictions.
- **Known limitations:** Accurate scoped report, not a generic “ready”.

## 8. Autonomous execution / escalation rule

**Solo-owner, chat-first content operation:** ChatGPT handles preparation, visual design, actual image creation when possible, registered metadata, canonical integration and verification through whichever authenticated tools are available. The VibeSchool HQ screen is optional and must not become an owner-operated prerequisite. An uploaded file, image made in chat, completed schema migration, recorded review and published image are distinct evidence states. If a connected storage-upload/publishing action is missing, complete the content package and report the precise tool boundary. Do not manufacture an asset ID, a published status or an independent approval.

**Routine production needs no repeat approval from the owner:** obtain official evidence, author, revise, check, map, create a release candidate and fix ordinary errors within existing capabilities.

Escalate only a **proven necessary** decision or capability boundary (for example, a true rights issue, consequential safety uncertainty or release authorization under the existing policy). Name the exact boundary and finish every safe preparatory task first. Never fabricate human verification or silently bypass a mandatory release gate.

## 9. Completion statement

Write one scoped statement grounded in evidence:

- **Content-complete for [exact scope]:** every applicable outcome packet has the required learning evidence.
- **Quality-checked for [exact version]:** the named quality checks and independent review (if required) passed, with references.
- **Published / learner-visible for [exact scope]:** existing release authority was satisfied and the real consumer journey was verified.

The three statements are **not interchangeable**. An unreviewed manuscript can be content-complete but not publication-ready. A repository policy commit can exist without any learner content being live.
