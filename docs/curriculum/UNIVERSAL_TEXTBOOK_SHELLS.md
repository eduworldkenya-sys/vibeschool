# Universal curriculum textbook shells

Owner decision, 18 November 2026: each registered/discoverable grade and subject has a book-shaped entry in the shared Learn library independently of authoring and publication. Chapters are projected from existing readable canonical CBC strands and sub-strands, not a separate curriculum store. Books may have zero or any number of chapters and topics. Missing mappings are not fabricated. The outline is metadata, not proof of curriculum verification, content completion or release. Existing published reader routes, entitlement and publication gates remain authoritative. No new production tables, publication records, user grants or automated publishing are needed for this first phase.

The first release exposes structural navigation separately from the existing published material list. Future content loading must preserve stable curriculum and publication identities and progressively connect released chapters to the corresponding outcomes. Do not create one book per delivery mode or require an entire book to be written before releasing an eligible existing chapter. No claim is made that every subject already has mapped curriculum records or that all learners can read those records under existing RLS.

## Persistent shells and curriculum connection — owner decision 18 November 2026
Use `ensure_curriculum_textbook_shell(p_grade, p_subject, p_connect)` through the existing authenticated teacher/admin publishing account. Set connect false to create a completely empty draft. Set it true after canonical curriculum ingestion to create missing draft section records, using one existing `vibe_chapters.sub_strand_id` per sub-strand. The strand is the reader chapter grouping and the sub-strand is its stored reading unit. Repeating the call preserves previous content, IDs and existing numbering; the RPC only appends missing unpaced, unambiguous identities. The grade and subject identity is author-scoped, and no subject is inferred when unavailable (including CRE vs generic Religious Education). Use canonical subject labels. The existing VibeTextbook authoring/reader remains the storage and delivery surface. An empty book is a legitimate draft, not a release candidate. Author against the actual chapter ID and canonical outcomes; use the existing outcome link and content package workflows to attach authored evidence, not empty claims. Current all-chapter publication lifecycle still requires non-empty sections; independent partial release needs a separate governed lifecycle change. No existing legacy publication is automatically adopted or altered.

An authorized session using the existing PostgreSQL administrative connection (current_user postgres) may pass the explicit eligible author UUID as fourth `p_author_id` argument. Authenticated callers cannot impersonate another author; the routine is SECURITY INVOKER and never grants new table permissions. Future ChatGPT content work must look up the actual approved academic publishing account before using this route. Use `select id, title, sub_strand_id, cbc_strand from public.vibe_chapters where publication_id = ... order by number` to target the existing subtopic rather than creating duplicates; retrieve canonical outcomes by `sub_strand_id` and attach content to the appropriate outcome via the existing authoring contracts.

Known label aliases (including CRE, IRE, HRE, Science & Technology, Creative Arts and Agriculture) resolve to the same explicit canonical subject identity. A generic Religious Education subject is not a substitute for a particular religious option. The status `connected` means actual mapped section rows are present, rather than merely a global subject record.
